# Бизнес-требования и спецификация системы SmartCast

## 1. Общие сведения и глобальная цель

* **Название проекта:** SmartCast
* **Цель проекта:** Разработать веб-сервис для загрузки и прослушивания аудиоконтента (подкастов и аудиокниг) с интерактивными текстовыми субтитрами, таймкодами и AI-выжимкой.
* **Основная ценность:** Экономия времени пользователя при изучении лекций/подкастов за счет быстрого поиска по тексту и мгновенного перехода к нужным моментам аудио.

---

## 2. Ролевая модель

### 2.1. Гость
* **Права и возможности:**
  * Просмотр публичного каталога (подкасты, категории, авторы).
  * Поиск и фильтрация контента по названиям и тегам.
  * Воспроизведение аудиозаписей в публичном плеере.
* **Ограничения:**
  * Нет доступа к субтитрам, AI-выжимкам, сохранению прогресса и функциям избранного.
  * Нет возможности оставлять оценки и загружать контент.
  * Нет сохранения истории прослушивания.

### 2.2. Слушатель
* **Права и возможности:**
  * Все права «Гостя».
  * Просмотр полной интерактивной расшифровки (субтитров) во время воспроизведения.
  * Клик по слову/фразе в субтитрах для навигации (перемотки) по аудио.
  * Просмотр AI-выжимки и автоматических таймкодов.
  * Сохранение подкастов в «Избранное» / «Закладки».
  * Доступ к личному кабинету (профиль, история прослушиваний, настройки).
  * Доступ к системе оценивания аудиоконтента.

### 2.3. Автор
* **Права и возможности:**
  * Все права «Слушателя».
  * Доступ к расширенному личному кабинету автора.
  * Загрузка новых аудиофайлов и обложек.
  * Редактирование и удаление собственных опубликованных материалов.
  * Просмотр текущего этапа обработки подкаста (Загрузка / AI-обработка / На модерации / Опубликовано / Отклонено).

### 2.4. Модератор
* **Права и возможности:**
  * Модерация загружаемого контента (удаление материалов, нарушающих правила).
  * Одобрение или отклонение публикаций.
  * Просмотр списков публикаций, находящихся на проверке.
  * Просмотр истории модерации и заблокированных материалов.
  * Обработка жалоб пользователей на контент.

### 2.5. Администратор
* **Права и возможности:**
  * Все права «Модератора».
  * Управление аккаунтами пользователей (блокировка/разблокировка, смена ролей).
  * Управление категориями и тегами на платформе.
  * Мониторинг системных логов, истории действий модераторов/администраторов и статусов фоновых задач обработки файлов.

## 3. Ключевые бизнес-сценарии

### 3.1. Загрузка медиаконтента (Автор)
1. **Заполнение формы:** Автор заполняет форму (название, описание, категория), загружает обложку и аудиофайл.
2. **Поддержка форматов:** Платформа принимает большинство популярных аудиоформатов (`.mp3`, `.wav`, `.m4a`, `.aac`, `.ogg`, `.flac`). Максимальный размер файла — до 100 МБ.
3. **Асинхронное конвертирование:** Загруженный файл отправляется на фоновую обработку, где приводится к единому оптимизированному формату для стриминга (например, MP3 128 kbps).
4. **Сохранение в S3:** Итоговый аудиофайл и обложка сохраняются в S3 (MinIO).

### 3.2. Фоновая обработка и AI (Система)
1. **Передача на обработку:** После загрузки аудио система отправляет событие через Apache Kafka на расшифровку в AI-сервис.
2. **Генерация данных:** AI-сервис генерирует и записывает в БД:
   * JSON-массив субтитров с временными метками для каждого слова.
   * Глобальную AI-выжимку (summary) и структуру глав.
   * Массив сущностей (спикеры, персонажи, термины) с привязкой к таймкодам.

### 3.3. Модерация контента (Модератор)
1. **Смена статуса:** После завершения AI-обработки подкаст переходит в статус «На модерации».
2. **Проверка:** Модератор проверяет загруженные метаданные, корректность сгенерированного текста и отсутствие нарушений.
3. **Публикация:** При одобрении статус меняется на «Опубликовано», и запись становится доступна в общем каталоге.
4. **Отклонение:** При отклонении подкаст отправляется автору на доработку с указанием причины.

### 3.4. Интерактивное прослушивание (Слушатель)
1. **Запуск плеера:** При запуске аудио открывается интерактивный плеер.
2. **Подсветка текста:** При воспроизведении аудио бегущая строка с текстом подсвечивает текущее произносимое слово.
3. **Навигация по клику:** При клике на любое слово в тексте или временную метку плеер мгновенно перематывает аудио на секунду, привязанную к этому слову.

### 3.5. Поиск и фильтрация контента (Гость / Слушатель)
1. **Ввод запроса:** Пользователь вводит ключевое слово в строку поиска или выбирает категорию.
2. **Поиск:** Выделенная нода поиска (Search Node на базе Apache Lucene) ищет совпадения по названию, описанию, тегам, имени автора и субтитрам.
3. **Выдача результатов:** Сервис возвращает список карточек подкастов с пагинацией (постраничным выводом).

### 3.6. Восстановление контекста прослушивания (Слушатель)
1. **Возврат к прослушиванию:** Авторизованный пользователь открывает ранее недослушанный подкаст (система считывает сохраненный прогресс, например, 14:20).
2. **Запрос выжимки:** Пользователь нажимает кнопку «Напомнить, что было до этого момента» или «Что было в прошлом временном отрезке».
3. **Выжимка:** Слушатель получает пересказ контекста, предшествовавшего текущей минуте.

### 3.7. Интерактивный контекст и справочник (Слушатель)
1. **Просмотр сущностей:** В плеере доступна панель «Контекст выпуска / Книги».
2. **Адаптация под тип контента:**
   * *Для подкастов:* Отображается список спикеров/гостей и ключевых упомянутых терминов/технологий.
   * *Для аудиокниг:* Отображается глоссарий персонажей и локаций.
3. **Фильтрация по текущему времени:** В списке отображаются только те сущности, которые уже встречались в записи до текущей секунды воспроизведения (защита от спойлеров).
4. **Быстрый переход:** Клик по сущности перематывает плеер на момент ее первого упоминания или подсвечивает связанные блоки в субтитрах.

### 3.8. Управление личной библиотекой и реакциями (Слушатель)
1. **Добавление в избранное:** Пользователь нажимает «Сохранить» на карточке подкаста или аудиокниги, после чего запись попадает в его личную библиотеку.
2. **Оценка контента:** Пользователь ставит оценку подкасту. Система пересчитывает средний рейтинг записи и обновляет его в каталоге.
3. **История прослушиваний:** Пользователь может зайти в раздел «История», увидеть список ранее начатых треков и прогресс прослушивания по каждому из них.

### 3.9. Управление профилем и ролями (Администратор)
1. **Управление пользователями:** Администратор открывает панель управления, находит пользователя по email или логину.
2. **Смена прав:** Администратор назначает пользователю роль (например, выдает права «Автора» или «Модератора») или блокирует аккаунт при нарушениях.
3. **Категоризация:** Администратор создает, редактирует или удаляет категории и теги, доступные авторам при загрузке контента.

### 3.10. Редактирование и повторная отправка контента (Автор)
1. **Уведомление о статусе:** Автор видит в личном кабинете, что его выпуск получил статус «Отклонено», и читает комментарий модератора.
2. **Внесение правок:** Автор редактирует текстовые поля или загружает новый файл обложки/аудио.
3. **Повторная отправка:** При сохранении изменений статус выпуска автоматически меняется на «На модерации», и запись снова попадает в очередь проверки модератора.

### 3.11. Аутентификация и регистрация (Гость)
1. **Регистрация:** Пользователь вводит email, логин и пароль. Запрос перенаправляется в провайдер аутентификации Keycloak, который создает учетную запись с ролью по умолчанию («Слушатель»).
2. **Вход в систему:** Пользователь вводит логин/email и пароль. Keycloak выполняет проверку учетных данных по протоколу OAuth2 / OpenID Connect и возвращает авторизационные токены.
3. **Обновление сессии:** При истечении срока действия токена доступа фронтенд автоматически запрашивает новый токен через Keycloak (Refresh Token) без разрыва сессии пользователя.

### 3.12. Обработка ошибок фоновой AI-обработки (Система / Автор)
1. **Фиксация сбоя:** Если сервис транскрибации или LLM возвращает ошибку, система фиксирует сбой.
2. **Смена статуса:** Статус подкаста меняется на «Ошибка обработки».
3. **Уведомление автора:** Автор получает сообщение об ошибке в личном кабинете с кнопкой «Перезапустить обработку».

### 3.13. Жалобы на контент и модерация комментариев (Слушатель / Модератор)
1. **Отправка жалобы:** Слушатель нажимает «Пожаловаться» под публикацией, выбирая причину.
2. **Формирование запроса:** В базе данных создается запись жалобы, которая попадает в ленту модератора.
3. **Решение модератора:** Модератор отклоняет жалобу или скрывает/удаляет материал с отправкой уведомления автору.

### 3.14. Удаление контента и каскадная очистка данных (Автор / Модератор / Администратор)
1. **Запрос на удаление:** Автор или Администратор удаляет подкаст/аудиокнигу.
2. **Очистка ресурсов:**
   * В БД каскадно удаляются или помечаются удаленными субтитры, глоссарий, AI-выжимки, история прослушиваний и рейтинг.
   * Бэкенд удаляет связанные медиафайлы из S3 (MinIO).

### 3.15. Управление очередью воспроизведения и автовоспроизведение (Слушатель)
1. **Формирование очереди:** Слушатель может добавить подкасты в очередь «Слушать далее» или запустить воспроизведение всего альбома/плейлиста по порядку.
2. **Автоматический переход:** По завершении текущего аудиофайла плеер автоматически загружает и запускает следующий трек из очереди без участия пользователя.
3. **Управление:** Пользователь может менять порядок треков в очереди или удалять их.

### 3.16. Расшаривание фрагмента аудио по таймкоду (Слушатель / Гость)
1. **Генерация ссылки:** Пользователь нажимает «Поделиться» и выбирает чекбокс «Начать с текущего момента (14:20)».
2. **Переход:** Гость или Слушатель, открыв полученную ссылку, попадает на страницу подкаста, а плеер автоматически запускается с 14:20 секунды.

## 4. Функциональные требования к модулям

### 4.1. Модуль аутентификации
* Система должна обеспечивать регистрацию новых пользователей через провайдер аутентификации Keycloak.
* Система должна выполнять аутентификацию пользователей по протоколу OAuth2 / OpenID Connect с выдачей токенов доступа через Keycloak.
* Система должна поддерживать механизм автоматического обновления токенов доступа через Refresh Token.
* Система должна обеспечивать корректный выход из системы (Logout) с аннулированием текущей сессии.

### 4.2. Модуль пользователей и ролевого доступа
* Система должна поддерживать ролевую модель разграничения доступа для 5 ролей: Гость, Слушатель, Автор, Модератор, Администратор.
* Система должна обеспечивать проверку прав доступа к REST API эндпоинтам на основе роли текущего пользователя.
* Администратор должен иметь возможность изменять роль любого зарегистрированного пользователя.
* Администратор должен иметь возможность блокировать и разблокировать аккаунты пользователей.
* Пользователь должен иметь возможность просматривать и редактировать данные своего профиля.

### 4.3. Модуль медиа
* Система должна поддерживать валидацию и загрузку аудиофайлов популярных форматов (`.mp3`, `.wav`, `.m4a`, `.aac`, `.ogg`, `.flac`) размером до 100 МБ.
* Система должна загружать бинарные файлы (аудио и обложки) в объектное хранилище MinIO (S3).
* Система должна выполнять асинхронную конвертацию исходных аудиофайлов в оптимизированный формат для стриминга.
* Система должна поддерживать жизненный цикл состояний подкаста: `Загрузка` -> `AI-обработка` -> `На модерации` -> `Опубликовано` / `Отклонено` / `Ошибка обработки`.
* Система должна обеспечивать каскадное удаление подкаста и всех связанных данных.

### 4.4. Модуль AI-обработки и транскрибации
* Система должна асинхронно отправлять загруженные аудиофайлы в очередь сообщений Apache Kafka для передачи в AI-сервис.
* AI-сервис должен генерировать расшифровку текста с временными метками для каждого слова в формате JSON.
* AI-сервис должен генерировать краткую текстовую выжимку и структуру глав.
* AI-сервис должен извлекать и классифицировать ключевые сущности (спикеры, персонажи, термины, локации) с их привязкой к таймкодам первого упоминания.
* В случае сбоя AI-обработки система должна переводить подкаст в статус ошибки обработки с возможностью повторного запуска Автором.

### 4.5. Модуль поиска, каталога и интерактивного плеера
* Система должна предоставлять публичный каталог с поддержкой поиска через Search Node (Apache Lucene) по названию, тегам, авторам и пагинацией результатов.
* Плеер должен обеспечивать стриминг аудиофайлов из S3.
* Плеер должен синхронизировать текущее время воспроизведения с подсветкой соответствующих слов в блоке субтитров.
* Плеер должен поддерживать мгновенную перемотку аудио при клике на любое слово в субтитрах или на сущность из глоссария.
* Система должна обеспечивать генерацию и обработку ссылок с временной меткой.
* Плеер должен поддерживать управление очередью воспроизведения и автопереход к следующему треку.

### 4.6. Модуль персональной библиотеки и взаимодействия
* Система должна сохранять и автоматически обновлять прогресс прослушивания для авторизованных пользователей.
* Система должна предоставлять функцию «Напомнить контекст» (выжимка событий/тем, предшествующих текущему времени воспроизведения).
* Система должна фильтровать сущности в глоссарии, скрывая не встречавшиеся ранее термины и персонажи (защита от спойлеров).
* Пользователь должен иметь возможность добавлять контент в «Избранное», просматривать историю и ставить оценки.

### 4.7. Модуль модерации и жалоб
* Модератор должен иметь доступ к очереди подкастов для их одобрения или отклонения с указанием причины.
* Слушатели должны иметь возможность отправлять жалобы на публичный контент.
* Модератор должен получать список жалоб и иметь возможность скрывать или удалять нарушающие правила материалы.

## 5. Нефункциональные требования (Технический стек и архитектура)

### 5.1. Архитектура и межсервисное взаимодействие
* **Топология:** Двухуровневая система с единой точкой входа через Reverse Proxy, маршрутизирующая запросы на Backend и Search Node.
* **Синхронные протоколы:** REST API (описанный через Swagger/OpenAPI) для обмена с клиентами и gRPC (ProtoBuf) для внутренних вызовов между сервисами.
* **Асинхронные протоколы:** Apache Kafka для передачи событий от основной бизнес-логики к сервису поиска, а также WebSocket для Push-уведомлений на клиент без опроса сервера.
* **Поиск:** Полнотекстовый поиск реализуется через выделенный микросервис (Search Node) на базе Apache Lucene.

### 5.2. Стек Backend-разработки
* **Платформа:** Java Development Kit (JDK) версии 21+ и Spring Boot (Spring Web, Spring JPA, Spring Security, Spring Session).
* **Сборка и тесты:** Maven для сборки проекта и TestNG для написания модульных тестов.
* **База данных:** PostgreSQL в качестве основного реляционного хранилища, миграции структуры БД контролируются через Liquibase.
* **Управление сессиями:** Распределенное хранение сессионных данных реализуется через Redis и Spring Session.
* **Хранилище медиа:** Объектное S3-совместимое хранилище (MinIO) для бинарных файлов.

### 5.3. Стек Frontend-разработки
* **Фреймворк:** React.js в связке с CSS-фреймворком Radix UI для построения компонентов.
* **Требования к UI/UX:** Адаптивный дизайн, клиентская и административная части работают через Reverse Proxy, реализован WebSocket-клиент для обработки уведомлений.

### 5.4. Инфраструктура, безопасность и мониторинг
* **Аутентификация:** Вход и авторизация управляются через отдельный сервис Keycloak по протоколам OAuth2 / OpenID Connect.
* **Контейнеризация:** Сборка и развертывание компонентов инфраструктуры осуществляется через Docker.
* **Мониторинг:** Использование Prometheus для сбора системных метрик и Grafana для визуализации дашбордов состояния IT-инфраструктуры.
